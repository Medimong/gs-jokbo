# 개념 페이지 작성 스펙 (에이전트 1개 = 개념 1개)

문항 해설은 그 문항에만 답한다. 개념 페이지는 **그 주제를 한 번에 끝내는 교과서 한 절**이다.
같은 개념을 참조하는 문항이 열 개라도 이 페이지 하나만 잘 쓰면 된다. 그러니 깊게 써라.

## 이 페이지의 존재 이유
문항 해설에서 가이드라인을 되풀이하지 않기 위해서다. Milan 기준이나 Rutherford 분류를
문항마다 선지 다섯 개에 쪼개 쓰면, 같은 내용이 반복되면서도 정작 "조건이 바뀌면 무엇이
달라지는가"는 한눈에 안 들어온다. 그 판단 기준을 **여기 표 하나로** 올려두면 문항 해설은
"이 환자는 이 칸에 해당한다"로 끝나고, 표는 다른 병기나 다른 등급의 환자를 만났을 때도
그대로 쓸 수 있다.

## 반드시 넣을 것: 판단 프로토콜
조건에 따라 처치가 갈리는 주제라면 **결정표 또는 단계별 프로토콜을 반드시 넣어라.**
이것이 이 페이지의 핵심이고, 없으면 반려된다.

### 결정표
조건을 행으로, 판단 결과를 열로 놓는다. 기준이 되는 수치는 원문 그대로 적는다.
크기, 개수, 등급, 나이, 검사 수치처럼 갈림길이 되는 값을 반드시 칸에 넣는다.
```html
<table><thead><tr><th>병기</th><th>종양 크기와 개수</th><th>간기능</th><th>일차 치료</th></tr></thead>
<tbody><tr><td>BCLC 0</td><td>단일 2cm 이하</td><td>Child-Pugh A</td><td>절제 또는 고주파열치료</td></tr>
...</tbody></table>
```

### 단계별 프로토콜
순서대로 판단해 내려가는 알고리즘은 `<ol class="flow">`로 쓴다. 각 단계 안에서 갈리는
분기는 `<ul>`로 중첩하고, 분기 항목은 "조건이면 결과" 꼴로 쓴다. 사이트가 계단 형태로
조판한다. 이 구조 외의 class나 태그를 쓰지 마라.
```html
<ol class="flow">
  <li>간외 전이나 대혈관 침범이 있는가
    <ul><li>있으면 BCLC C, 전신치료</li><li>없으면 다음 단계</li></ul></li>
  <li>종양이 Milan 기준을 만족하는가 (단일 5cm 이하, 또는 3개 이하이면서 각 3cm 이하)
    <ul><li>만족하고 간기능이 나쁘면 간이식</li><li>만족하고 간기능이 좋으면 절제</li></ul></li>
</ol>
```

## 원칙
- 대상은 외과 실습을 도는 본과 3학년이다. 처음 보는 개념도 이해할 수 있게 풀어 쓰되,
  **쉽게 쓰는 것이 얕게 쓰는 것은 아니다.** 개념을 한 번 친절히 소개한 뒤에는
  병태생리, 감별, 수치 기준, 가이드라인 권고까지 전문적인 내용으로 들어간다.
- 항목을 나열하지 말고 **읽으면서 이해가 이어지도록** 서술한다. 질환이나 술식 하나를
  단위로 묶어 정의, 발생 맥락, 판단 기준, 처치, 주의점 순으로 문단을 쓴다.
  짧은 목록은 마지막 요약에만 쓴다.
- 감별이 핵심인 주제는 **비교표**를 반드시 넣는다. 표가 이 페이지의 핵심 자산이다.
- 근거는 Sabiston, Schwartz, 대한외과학회 진료지침, NCCN, ATA 등 표준을 쓴다.
  가이드라인 개정으로 예전 족보와 답이 갈리는 지점이 있으면 그 사실을 명시한다.

## 표기 규칙 (문항 해설과 동일)
- 의학용어와 해부학 구조물은 한글과 영어를 함께 적는다. 처음 나올 때
  "췌십이지장절제술(pancreaticoduodenectomy)"처럼 쓰고 이후에는 한쪽만 써도 된다.
- 화살표(→, ←, ⇒), em dash, 하이픈 두 개(--), 글머리 이모지를 쓰지 않는다.
  대신 쉼표, 마침표, 괄호, "즉", "이후", "따라서"를 쓴다.
- 강조는 한 단락에 하나까지.
- 문어체로 쓴다.

## 출력
`concepts/{slug}.json` 한 파일.
```json
{
  "slug": "gastrectomy-types",
  "title": "위절제술의 종류와 적응증",
  "section": "UGI",
  "summary": "한 문장으로 이 페이지가 무엇을 정리하는지.",
  "body": "<h3>...</h3><p>...</p><table>...</table>",
  "related": ["다른-개념-slug"],
  "source_qids": [51]
}
```
- `slug`는 영문 소문자와 하이픈만 쓴다(파일명 안정성 때문이다).
- `body`는 HTML 문자열이다. 쓸 수 있는 태그는 `h3 p table thead tbody tr th td ul ol li strong em code`뿐이다.
  class는 단계별 프로토콜의 `<ol class="flow">` 하나만 허용한다. style 속성은 쓰지 마라.
- 분량은 주제가 요구하는 만큼. 결정표와 감별표가 있는 주제라면 대략 4000자에서 8000자다.
- `protocol`에 이 페이지가 담은 판단 기준의 이름을 적는다. 예: `["Milan criteria", "BCLC staging"]`.
- JSON에 리터럴 개행을 넣지 마라.

## 임시 파일 이름 규칙
작업 중 스크립트나 임시 파일을 만들어야 하면 **파일 이름에 담당 문항 번호나 slug를 넣어라**
(예: `/tmp/build_q2532.py`, `/tmp/card_pheochromocytoma.py`). 여러 에이전트가 동시에 돌기
때문에 `build.py`, `tmp.json` 같은 흔한 이름을 쓰면 서로 덮어쓴다. 실제로 겪었다.
